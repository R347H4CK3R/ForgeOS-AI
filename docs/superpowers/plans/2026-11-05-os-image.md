# ForgeOS offline GSI adaptation implementation plan
Goal: produce a real experimental Android system filesystem with the verified native workstation integrated, without modifying or booting the tablet.
Architecture: inspect a pinned upstream vanilla Android15 ARM64 GSI on an isolated GitHub worker, then adapt a copy using offline ext4 tools. Preserve existing inode metadata and upstream notices. Keep full AOSP product source as the long-term source-build route.
Tech: Python standard library, e2fsprogs/debugfs, Android SDK/aapt2, GitHub Actions.
Spec: owner's ForgeOS mission and UI approval; os/docs/recovery-and-installation-gates.md.
Global constraints: no device writes, reboots, bootloader operations, wipes, flashes or SD migration; no heavy laptop builds; no claim of target compatibility; no reuse of upstream vbmeta for modified bytes.

## Review focus
Wrong architecture/API; stale signatures/AVB footer; dropped SELinux labels; disabled static overlays; incorrect source provenance and notices. Each must appear in inspection/evidence and fail closed where required.

## Tasks
- [x] 1. Baseline inspector: os/image/base.lock.json pins release/asset/size; os/image/image_tools.py validates hashes, ext4 format and metadata. Tests reject hash/size/format mismatch and block-device paths. A bootstrap inspection records a computed SHA when publisher provides none; adaptation remains blocked until pinned.
- [x] 2. Offline adapter: os/image/build_image.py copies regular files only, integrates the exact hash-pinned ARM64 APK without granting system UID/privileges, explicitly assigns new node ownership/modes/SELinux contexts, enables only validated freeform integration, verifies extracted bytes and unchanged existing metadata, emits fsck/hash/provenance reports. Tests use a synthetic real ext4 image and malformed inputs.
- [x] 3. CI: .github/workflows/os-image.yml validates source and runs explicit inspect/build dispatches; no generic URLs or device tools. Image artifacts labelled EXPERIMENTAL-DO-NOT-FLASH and never accompanied by stock vbmeta/flash scripts. APK CI path filters prevent unrelated OS changes rebuilding app jobs.
- [x] 4. Review and evidence: inspect actual upstream APK overlayable tables and overlay config before constructing any RRO; record license/provenance and known upstream network defects. Update OS matrix, recovery findings, generated artifact hashes and source-build instructions. Review source and actual workflow outputs before completion claims.

Shared interfaces: lock SHA/size/API feed inspector and adapter; inspector reports system-root and metadata used by adapter; CI supplies the verified APK from source cf01a34 artifact. Ruling: a SHA computed at bootstrap is an observed pin, not a publisher-authenticated checksum. Exact recovery/AVB/vendor checks remain installation gates, not a claim that this offline artifact can boot.
Owner chose autonomous execution; proceed through implementation and isolated validation. UI approved; no OS boot/flash/unlock authorization inferred.

Implementation ruling: actual Android15 framework supportsMultiWindow=true; obsolete freeform bool absent. Freeform feature declaration is used; no unnecessary RRO is shipped. Image source is pinned vanilla GSI adaptation, not full-source AOSP. Stable APK signing and RSA-signed staging catalogs are implemented; final integrated build evidence is recorded in OS review. Target boot acceptance remains blocked.
